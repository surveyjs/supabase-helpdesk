# UI/UX review and import check — 2026-11-12

Instance: local deploy bundle at `http://127.0.0.1:8080`, AnswerDesk 10 % sample loaded
(2,544 tickets, 11,468 posts, 2,949 attachments, 7,519 users). Signed in as the bootstrap admin via
`/login?no_redirect=true`.

How it was tested: a read-only Playwright walkthrough (no clicks that change data) over every route
at 1440 px (desktop), 820 px (tablet) and 390 px (phone), plus 15 hand-picked imported tickets that
cover the import edge cases. Per page it recorded HTTP status, console errors, failed requests,
horizontal overflow, broken images, unlabeled inputs and small tap targets. The regular
`npm run test:e2e` suite was **not** run against this instance: it seeds users and tickets and
forces `auth_mode=built-in`, which would pollute the imported data.

Priority: **P1** broken / blocks a task, **P2** clearly wrong or ugly, **P3** polish.

## 1. Import check

What is fine:

- DB counts equal the staged counts in `adimport.runs` (tickets 2,544, posts 11,468, attachments
  2,949, users 7,516 + existing, 6,112 `custom:external` identities, 207 CSAT, 573 ticket tags).
- 36 of 37 app routes return 200 for the admin with no console or JS errors. `/help` is a 404
  because `kb_visible=false`, which is expected, but it then hits the 404 bug B1 in §2.
- Ticket pages render imported Markdown correctly: code fences, links, nested comments
  ("Show 47 earlier comments" collapse), private posts, duplicate banner, custom fields
  (License Status / Is License Owner), CSAT, tags.
- Inline images (`/attachments/<id>`) and attachment links resolve to signed Storage URLs and return 200
  with correct MIME types (png, jpeg, gif, pdf, json, mp4 sampled).
- *(attachment not migrated)* markers render as italic text (115 posts).
- No raw HTML / Markdown leaks outside code blocks on the sampled tickets.
- A wrong slug (`/tickets/1435/wrong-slug`) redirects to the canonical slug.

Problems:

| # | Pri | Finding | Suggestion |
|---|---|---|---|

## 3. UI/UX improvements by area

### 3.1 Global / navigation

- **P2 — Home page is nearly empty for agents and admins** ("Welcome, me / A customer-support ticket system." on a blank page). Redirect agents to `/agent`, and give users a "My tickets" summary + "New ticket" button.
- **P2 — Key destinations are buried in the user dropdown** for agents/admins (Setup, My Tickets, Reports, Canned Responses). The top bar has lots of free space; put Reports and Setup (admin) in the top nav and keep the dropdown for personal items (Profile, Notifications, Sign out).
- **P3 — The "Admin" role badge is red/pink**, which reads as an error or warning. Use a neutral or brand color (gray/indigo) for role badges.
- **P3 — Display name "me"** (derived from the e-mail local part) appears as "Welcome, me" and in the nav. Prompt for a display name on first login, or fall back to the full e-mail.
- **P3 — Page widths are inconsistent:** most pages use `max-w-5xl`, `/notification-settings` uses a narrower centered column (title starts at x=336 vs x=224). The full-width ticket page is by design (docs/design.md). Pick one content width per page type and align headings to the same left edge.
- **P3 — Mixed form-control styles:** native `<select>`/checkbox (Create Ticket, Reports, User Management filters, Notification Settings) next to SurveyJS-styled dropdowns and switches (ticket sidebar, Agent dashboard filters, Tiers). Height, radius, border color and chevron differ. Converge on one control style (one Tailwind component set, or style native controls to match).

### 3.2 Agent dashboard (`/agent`)

- **P2 — Badge colors carry no meaning.** Urgency "Medium" and Severity "Medium" use the same mint/green pill as "Open" status, so green no longer means "open/good". Use a neutral pill for Medium, amber for High, red for Critical/Urgent, and keep green for status only. Different shapes or icons for urgency vs severity would help too.
- **P2 — "Closed" status pill is almost invisible** (light gray on white). Fine to de-emphasize, but give it a visible border or darker text (`text-gray-700`, `bg-gray-100`, `ring-1 ring-gray-200`).
- **P2 — Tablet (820 px): the table is cut off on the right** (Posts and Updated are off-screen, with no scroll hint). Switch to the card layout below `lg`, or hide low-value columns (SLA, Posts) below `xl`.
- **P2 — Rows are very tall** because titles wrap to 3 lines and submitter names wrap (e.g. "Transfered / Licence / Owner"). Clamp titles to 2 lines (`line-clamp-2`) with the full title in a tooltip; give the submitter column `whitespace-nowrap` + truncate; reduce row padding (`py-3` → `py-2`) for a denser list.
- **P3 — Lock emoji 🔒 for private tickets** renders in color and differs per OS. Use the same outline lock icon as the "Internal notes" tab, in gray.
- **P3 — SLA column shows "—" for every ticket.** Hide the column when no SLA policy exists.
- **P3 — Pagination for 128 pages shows only 1–5 + Next.** Add Previous, First/Last, the current page, and "1–20 of 2,544". Same on User Management ("Page 1 of 376", Next only).
- **P3 — Mobile cards:** the checkbox column wastes ~60 px on the left; the single "Medium" pill doesn't say whether it is urgency or severity; submitter and post count are missing. Put the checkbox inline with the title or hide bulk-select on phones; label pills ("Urgency: High") or show only non-default values.
- **P3 — Filter panel:** status checkboxes say **"Active"** while badges say **"Open"** (and `/tickets` tabs also use "Active"). Use one term everywhere. "Sort By" shows the placeholder "Select…" instead of the actual default sort. Consider a compact horizontal filter bar for the 3–4 most-used filters, with the rest under "More filters".

### 3.3 Ticket page (`/tickets/[id]/[slug]`)

- **P2 — Post actions are split over two lines**: "Edit" alone on one line, then "Delete ☐ Private Clone to new ticket" on the next, all in different colors (red, gray, blue). Put all actions in one row at the post footer (or in a "⋯" menu), muted gray until hover. Keep Delete red only inside the confirm step.
- **P2 — The disabled "Delete Ticket" button shows a red error message** "Closed tickets cannot be deleted. Re-open first." on every closed ticket, which looks like something went wrong. Hide the row for closed tickets, or show the hint as gray helper text or a tooltip on a disabled button.
- **P2 — "Advanced" actions use three different pill colors** (yellow Mark as Duplicate, purple Merge into…, blue Clone), and "Merge into…" is truncated. Use one secondary-button style in a vertical list or a "More actions" menu.
- **P3 — Sidebar duplicates information:** the follower count appears twice ("3 followers" at the bottom of the first card and "Followers 3 followers" in the second card), and tags appear twice (in the Tags select and again as a dark pill under SLA, #43). Merge the second info card into the first and drop the duplicates.
- **P3 — Sidebar spacing:** large gaps between the "Private ticket" and "Follow this ticket" checkboxes; label/field rhythm is uneven ("Created by / Advanced / Created / Updated / Delete" is a compact key-value list right under roomy form fields). Group into sections with small headings: *Properties*, *People*, *Dates*, *Actions*.
- **P3 — The ticket number "#1435" is a tiny gray label** at the top of the sidebar. Show it next to the title (`#1435 · Is it possible…`), which is where agents look for it when referencing tickets.
- **P3 — The title edit pencil** is a small blue glyph glued to the title. Show it on hover, gray, with a larger hit area.
- **P3 — Phone:** nested comments indent ~40 px, which leaves little width for code blocks. Reduce the indent to 12–16 px on small screens and rely on the left border line.
- **P3 — Reply box** "Reply to this ticket…" looks like a disabled input. Give it the same border/height as the expanded editor, and for closed tickets say "Replying will re-open this ticket" (if that's the behavior).

### 3.4 Create ticket (`/tickets/new`)

- **P3 — The editor opens in split mode with an empty preview pane** taking half the width. Default to write mode with a Preview tab, or show preview only on wide screens once there is content.
- **P3 — Editor toolbar icons** are small and low contrast (`#999`-ish on light gray). Increase to 18–20 px, `text-gray-600`, add tooltips.
- **P3 — "Is License Owner"** is a bare checkbox under its label here but a No/Yes segmented switch in the ticket sidebar. Use the same control in both places.
- **P3 — Cancel and Create Ticket are equal-width full-row buttons.** Use right-aligned buttons with Create as primary and Cancel as a text/secondary button.

### 3.5 Reports (`/reports`)

- **P2 — The first card (Ticket Volume) has no title** when empty; only "No data for this period" appears. Always show card titles.
- **P3 — Export button labels are auto-capitalized wrongly:** "Csat Summary", "Sla Compliance" ([ReportControls.tsx:199-201](../src/components/features/reports/ReportControls.tsx#L199-L201) uses `capitalize` on `type.replace(/_/g,' ')`). Use an explicit label map (CSAT Summary, SLA Compliance).
- **P3 — Period presets stop at 90 days**, but the imported history spans 2017-06 … 2026-03. Add "Last 12 months" and "All time".
- **P3 — Three control rows of different sizes** (period buttons, filter selects, tiny export buttons). Put export in a single "Export ▾" menu at the top-right, and align the selects with the period buttons.

### 3.6 Setup / admin

- **P2 — Subscription Tiers:** an empty matrix shows column headers with nothing under them, and the save button is labeled "Complete" (SurveyJS default), which doesn't mean "save" to an admin. Add an empty state ("No tiers yet — Add your first tier") and rename the button to "Save changes" (`completeText`). The cURL usage block overflows the card at 1440 px; wrap it in `overflow-x-auto`. The API endpoint shows `http://localhost:8080` while the app is opened at `127.0.0.1:8080` (it comes from `APP_URL`, so that's config, but worth a note in the deploy docs).
- **P3 — User Management:** Role is plain text; show it as a badge (same style as the nav). Team and Tier columns are "—" for all 7.5k rows; hide empty columns or move them to the detail view. There is no Status/Blocked column although there is a Status filter. On phones the table is cut after Email (Role is invisible): use cards on small screens. On phones the "Reset" button wraps onto its own line under "Filter".
- **P3 — `/admin` redirects to `/admin/types`.** A small overview page (counts, auth mode, e-mail status, warnings such as "Shared secret not configured") would be a better landing page.
- **P3 — The setup sidebar is long** (25 links). The "Filter settings…" box helps; making the sidebar sticky with its own scroll would keep it usable on long pages (Templates is 4,500 px tall).
- **P3 — Warning text color:** "Not configured — external tier assignment is unavailable" is orange text on white with low contrast. Use an amber callout box with an icon.

### 3.7 Login (`/login?no_redirect=true`)

- Looks clean. **P3:** the "ADMINISTRATOR SIGN-IN" divider label is very small and light. Consider a collapsible "Sign in with password (administrators)" link instead, so regular users aren't tempted to use the password form.

## 4. Re-running the walkthrough

The scripts used for this review live outside the repo (scratchpad). If this check should be repeatable, turn
them into a `tests/e2e-readonly/` Playwright project that targets `BASE_URL` and does no writes. It would:

1. sign in via `/login?no_redirect=true`,
2. visit every route at 1440/820/390 px,
3. fail on console errors, 4xx/5xx responses, horizontal overflow and broken images,
4. open a list of ticket ids and assert that no `{'Id':` / `{'FriendlyId':` / `CheckAnswerDesk` text is
   rendered and that every `/attachments/` link returns 200.

Block non-local hosts in that project (`context.route`), because `/login` auto-redirects to the SSO provider.
